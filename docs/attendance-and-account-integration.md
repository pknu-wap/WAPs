# 출석 및 기존 계정 화면 통합

기준은 최신 `main`의 `b666fff`이다. 11월 12~21일 작업 중 이미 반영된
전체 선택·계정 삭제·LEVEL 필터·회원가입 입력 검증은 main 구현을 유지한다.

## 복원한 가입 정보 수정

- 설정에서 가입을 완료한 카카오 계정은 `/signup?edit=true`로 이동해 기존 이름과 학번을 수정할 수 있다. 클라이언트는 `GET /user/me`의 `registrationEditable` 값으로 수정 버튼과 직접 링크의 접근을 결정한다.
- 최초 가입은 기존 `POST /user/signup` 계약을 유지한다.
- 수정은 `PATCH /user/registration`을 사용한다.
  요청 예: `{ "member": true, "name": "홍길동", "studentNumber": "26" }`.
- `GET /user/me`의 `wapMember`는 본인이 입력한 회원 여부이며,
  관리자가 정하는 ROLE과 membershipLevel을 변경하지 않는다.
- 회원 여부를 false로 바꾸면 학번을 지운다. 수정 화면을 닫아도 로그인은 유지한다.
- 기존 회원 단계와 권한 관리·계정 삭제 구조를 이전 버전으로 되돌리지 않는다.

## 출석 수정 세 항목

1. 진행 중 출석과 종료 후 수정 모드에서 지각을 선택·저장한다.
   지각 인원은 별도로 집계하며 QR 재스캔으로 지각 상태나 최초 출석 시각을 덮어쓰지 않는다.
2. 출석체크와 설정 상단에 기존 WAPs 로고를 공통 컴포넌트로 배치한다.
3. QR 링크와 카메라 인식 모두 성공 후 완료 알림창을 표시한다.
   확인 후 이동하며, 화면의 고정 완료 버튼은 제거한다.

## 배포 전 확인

- 서버와 DB에 `V24__add_late_attendance_status.sql`, `V25__add_wap_member_profile.sql`을 함께 반영해야 한다.
- 프론트만 실행하면 기존 개발 API에는 지각 저장 및 가입 정보 수정 API가 아직 없을 수 있다.
- MySQL 통합 테스트는 별도의 `ATTENDANCE_TEST_URL`이 설정된 테스트 DB에서 실행한다.
  운영·개발 DB에 테스트 스키마를 생성하지 않는다.
