# 계정 삭제 및 재가입

- 관리자 회원 삭제는 계정 비활성화입니다. 사용자 행과 ID, 이메일, 기존 프로젝트·댓글·출석·팀 연결은 보존합니다. 개인정보를 완전히 파기하는 기능과는 다릅니다.
- 삭제 계정은 로그인, 토큰 갱신, 회원 관리 목록, 프로젝트 팀원 후보, 신규 출석 대상에서 제외됩니다. 기존 콘텐츠와 출석 기록은 유지됩니다.
- 카카오에서 동일 이메일의 유효성과 인증 여부를 확인한 경우 기존 ID로 복구하고 가입 정보 입력으로 이동합니다.
- 삭제 시 기존 비밀번호 해시를 제거합니다. 로컬 재가입은 같은 이메일이면 기존 ID와 연결 정보를 자동 복구하고 새로 입력한 비밀번호를 해시하여 저장합니다. 기존 비밀번호는 요구하거나 복원하지 않습니다.
- 현재 로컬 가입에는 이메일 소유 확인 기능이 없습니다. 따라서 삭제 계정의 이메일을 아는 사람도 해당 계정의 연결 정보를 복구할 수 있는 정책입니다. 카카오 재가입은 공급자가 확인한 이메일로 자동 복구합니다.
- 복구 계정의 권한은 GUEST, 회원 등급은 NONE입니다. 관리자 및 정회원 권한은 다시 승인받아야 합니다.
- 삭제 시 refresh token을 지우고 토큰 버전을 올립니다. 복구 때도 버전을 올려 삭제 전 access/refresh token을 재사용할 수 없게 합니다. 기존 버전 없는 JWT는 버전 0으로 취급하여 미삭제 회원의 세션을 유지합니다.
- 개발용 고정 슬롯 계정은 삭제 후 슬롯 로그인으로 자동 복구하지 않습니다.

## 배포

V21 마이그레이션이 `user.deleted`, `user.token_version`을 추가합니다. 새 서버 코드와 함께 적용해야 하며, 이전 서버 인스턴스가 삭제 계정을 허용하지 않도록 구버전 서버를 함께 운영하지 마세요. 이미 물리적으로 삭제된 계정 및 연결 데이터는 이 변경으로 복원할 수 없습니다.

V22 마이그레이션은 이전 구현으로 이미 삭제 처리된 계정에 남아 있는 비밀번호 해시도 제거합니다.

## 검증

`./gradlew test --tests '*Test'`로 외부 DB가 필요한 `ServerApplicationTests`를 제외한 테스트를 실행합니다. 계정 삭제 통합 테스트는 H2에서 실제 외래 키 연결을 유지하며 삭제/복구, 비밀번호 삭제, 목록 제외, refresh token 제거를 확인합니다. 인증 테스트는 새 비밀번호로 자동 재가입, 활성 계정 중복 가입 거부, 카카오 이메일 검증, 권한 초기화, 삭제 전 JWT/refresh token 거부를 확인합니다.
